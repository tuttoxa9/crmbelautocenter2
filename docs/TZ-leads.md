# ТЗ. Раздел «Лиды»

Документ закрывает переработку раздела «Лиды» в CRM Белавтоцентр и связку входящих заявок с машинами склада. Код по этому ТЗ не пишется, пока документ не принят.

Репозитории:

- CRM: `crmbelautocenter2`, экран `/leads`.
- Сайт: `belautocenter2`, приём форм и вебхук Meta.

Остальные разделы CRM не перекрашиваются: комиссия, реклама TikTok, качество, цели, бюджет, файлы, настройки, вход.

## 1. Задача

Сделать раздел рабочим столом менеджера: серьёзным, просторным и одинаково собранным на каждом шаге. Весь текущий функционал сохраняется. Меняется подача и добавляется точная привязка заявки к машине склада.

Привязка берётся из уже готовых пар Ads Manager на сайте. Кампания «Лиды — видеообзоры авто». Пара хранится как объявление → машина: ручной выбор или автопара по марке, модели и году. CRM не угадывает другую машину по похожему названию.

## 2. Что остаётся в данных и правилах

Статусы не меняются: Новый, В работе, Приезд, Перезвонить, Недозвон, Думает, Оформился/купил, Отказ, Отказ банка, Брак/Тест.

Лизинг отдельным статусом не заводится. Заявка, которую смотрит лизинговая компания, остаётся «В работе». День, когда менеджер проверяет ответ, ставится следующим шагом. В заметке пишется, что документы в лизинге. Напоминание в Telegram уходит по уже сохранённому правилу статуса «В работе»: за выбранные минуты до этого шага, один раз на эту дату. Новое правило, новая колонка слева и новый пункт в списке статусов не появляются.

Источники в базе не меняются: сайт, Instagram, TikTok, звонок, интеграция, Телеграм, с улицы, Куфар. Заявка из формы Meta по-прежнему пишется как `instagram`. В интерфейсе такая заявка подписывается «Meta», если в ней есть идентификатор объявления или формы. Остальные `instagram` остаются «Instagram».

Живая лента по-прежнему слушает только рабочие статусы: Новый, В работе, Приезд, Недозвон, Думает, Перезвонить. Оформился, Отказ, Отказ банка и Брак живут в «Базе» и в истории досье машины.

У лида остаются имя, телефон, текст авто, список машин склада, основная машина, источник, статус, дата следующего шага, заметка, IP, история, исходный пакет.

Список «Сегодня» внутри одного статуса остаётся одним, от новых к старым. Деления утро / день / вечер нет и не появляется.

Перевод в «Оформился/купил» по-прежнему один раз вызывает текущую отправку конверсии. Повторное сохранение того же статуса конверсию не шлёт.

Телеграм по лиду Meta остаётся одним сообщением с сайта. CRM свою копию не шлёт. Заявки «новый автомобиль в каталоге» в CRM не попадают.

Раздел видит только роль admin. Комиссия уходит на «Комиссию», SMM на «Мои цели». Чужие роли этот экран не получают.

## 3. Визуальная система

Название системы: «Кабинет».

Это инструмент продаж, а не витрина и не потребительское приложение. Текущий чёрный экран с белыми таблетками заменяется целиком: другие поверхности, другая типографика, другие состояния, другие отступы. Белая капсула как способ показать «выбрано» больше не используется.

### 3.1. Цвет

Тёмный графит, тёплый светлый текст, одна светлая команда для главного действия.

| Роль | Значение |
| --- | --- |
| Фон страницы | `#101114` |
| Поверхность списка | `#17191e` |
| Приподнятая карточка и лист | `#1e2128` |
| Линия | `rgba(255,255,255,0.08)` |
| Текст | `#f3f0e8` |
| Вторичный текст | `#a39e93` |
| Третичный текст | `#6f6a62` |
| Главная кнопка | фон `#f3f0e8`, текст `#16140f` |
| Тихая кнопка | прозрачный фон, линия, текст `#f3f0e8` |
| Опасное действие | `#c4554a`, только удаление, ошибка сохранения и отказ банка |

Статус — это цветная метка 8×8 и короткая подпись. Крупных цветных плашек нет. Цвета приглушённые:

| Статус | Метка |
| --- | --- |
| Новый | `#8ea0b5` |
| В работе | `#c4a15a` |
| Приезд | `#8d84b8` |
| Перезвонить | `#b7a06a` |
| Недозвон | `#b5836a` |
| Думает | `#7f92b0` |
| Оформился/купил | `#7d9a78` |
| Отказ | `#8a867e` |
| Отказ банка | `#c4554a` |
| Брак/Тест | `#5e5a55` |

Выбранная строка светлеет на одну ступень поверхности. Слева остаётся метка статуса. Подсветка только что найденного клиента — тёплая заливка на 2,4 секунды, без жёлтой рамки.

Проданная машина в мирном контексте подписывается «Продана» третичным текстом. Если по ней ещё есть рабочий лид, в карточке лида одна строка: «Машина уже продана».

### 3.2. Типографика и ритм

Системный шрифт: `-apple-system`, `Segoe UI`, без подключения нового семейства.

| Элемент | Размер и вес |
| --- | --- |
| Имя в карточке | 32 / 560, межстрочный плотный |
| Заголовок машины в досье | 22 / 560 |
| Имя в строке | 16 / 560 |
| Телефон, цена, дата | 14 / 500, цифры табличные |
| Основной текст и заметка | 15 / 400, межстрочный 1.45 |
| Подпись поля | 13 / 500, обычный регистр |
| Счётчик | 12 / 500 |

Подписи полей не кричат прописными. Прописные остаются только у короткого счётчика группы, если он стоит рядом с названием дня.

Отступы страницы: 20 на телефоне, 28 на столе. Строка лида не ниже 76. Радиус листа 20, радиус карточки машины 16, радиус поля 12, радиус главной кнопки 12. Пузыри на весь экран не используются.

Между блоками карточки 28. Внутри блока 8–12.

### 3.3. Фото и пустые картинки

Фото машины — единственное насыщенное изображение. В строке миниатюра 40×40, в карточке кадра 16:9 на всю ширину листа, в сетке «Авто» кадр 16:10. Если фото нет, поверхность `#262930` и первая буква марки. Битое фото заменяется тем же запасным видом, строка не прыгает.

### 3.4. Движение

Переходы 160–220 мс, только прозрачность и короткое смещение. Без пружин, без масштаба кнопки при наведении, без сдвига вёрстки. Нажатие видно сменой фона. У каждого нажимаемого элемента виден фокус с клавиатуры: линия 2 px цвета текста с отступом 2 px.

### 3.5. Состояния загрузки

Текста «Загрузка…» как единственного содержимого экрана нет.

- Первое открытие «Дня»: шесть скелетонов строки. У скелетона те же поля, что у будущей строки: метка, две линии текста, прямоугольник миниатюры, короткая линия времени.
- «Авто»: шесть скелетонов карточки с кадром 16:10.
- «База» и догрузка: три скелетона под уже показанными строками.
- Поиск: уже известные совпадения остаются на экране. Над списком строка «Проверяем всю базу», пока архив не дочитан.
- Кнопка в работе не меняет ширину. Подпись остаётся, кнопка гаснет и не нажимается. «Сохранить» на время запроса читается «Сохраняем».
- Общий спиннер приложения на входе в CRM не трогаем.

### 3.6. Пусто и ошибка

Пустое состояние — одна строка по центру рабочей области и, где уместно, одно действие. Ошибка — та же зона, текст что случилось, кнопка «Повторить». Уже загруженные данные при ошибке следующей порции не стираются.

Копирайт пустых состояний задан в сценариях ниже. Общих «Пусто» и «Ничего не нашлось» без предмета не остаётся.

## 4. Каркас экрана

Сверху одна полоса на всю ширину раздела.

Слева сегмент из трёх режимов: День, Авто, База. Выбранный режим — светлая главная кнопка. Остальные — тихий текст. Выбор пишется в `localStorage` ключ `leads.mode` и восстанавливается при следующем заходе. Неизвестный ключ открывает «День».

По центру поле поиска. Иконка лупы, плейсхолдер «Имя, телефон или авто». Клавиша `/` вне полей ввода ставит сюда фокус и не вставляет символ. Очистка крестом появляется, когда в поле есть текст.

Справа на «Дне», если открыт не статус «Новые» и поиск пуст, шаговик даты: назад, подпись дня, вперёд. Сегодня подписывается «Сегодня» и выглядит выбранным днём, а не отдельной таблеткой. На статусе «Новые» и во время поиска шаговика нет.

Кнопка «Клиент» в той же полосе на ширине от 768. Ниже 768 она закреплена справа снизу и не перекрывает последнюю строку: у списков нижний отступ 96.

Телефон, ширина до 767:

- В «Дне» сначала колонка статусов. Выбор статуса открывает список и прячет колонку. Над списком текст «Статусы» возвращает к колонке.
- Поиск не пустой сразу показывает результаты и прячет колонку статусов.
- Кнопка «Клиент» в колонке статусов на всю ширину, плавающая кнопка в этот момент скрыта.

Стол, ширина от 1024:

- Колонка статусов 240, список занимает остальное.
- Сетке «Авто» три колонки от 1280 и две от 768 до 1279. До 767 одна колонка.
- Горизонтальной прокрутки страницы нет на 375, 768, 1024 и 1440.

## 5. Режим «День»

Колонка статусов, сверху вниз: Новые, В работе, Приезд, Перезвон, Недозвон, Думает. Подпись «Перезвон» в колонке короче полного «Перезвонить» в карточке. Счётчик справа — число живых лидов этого статуса, без учёта выбранного дня. Нуль не показывается. Выбранный статус пишется в `leads.tab`. Битый ключ открывает «В работе».

### 5.1. Новые

Группы по календарному дню создания. Сначала сегодняшний день, затем более ранние. Внутри дня один список: сначала самый новый `createdAt`. Заголовки групп: «Сегодня», иначе «5 октября». Счётчик группы — число строк в ней.

Шаговик даты этот статус не фильтрует. Просрочки здесь нет: у нового лида нет следующего шага.

Пусто при пустом поиске: «Новых заявок нет».

### 5.2. Остальные рабочие статусы

Берётся выбранный день.

Если выбран не сегодня, на экране одна группа с названием дня. В неё попадают лиды, у которых день следующего шага совпадает с выбранным. Если следующего шага нет, используется день создания. Внутри группы порядок: более поздний шаг выше. При равном шаге выше тот, кто создан позже.

Если выбран сегодня, две группы, когда в них есть строки:

1. «Сегодня». Лиды, чей шаг приходится на сегодня. Порядок как выше.
2. «Просрочено». Лиды, чей шаг раньше сегодня. Внутри — подгруппы по дню, свежий просроченный день выше. Подпись дня: «Вчера» или «4 октября, сб». Внутри дня более поздний шаг выше.

Пустая группа не рисуется. Если обеих нет: «На этот день пусто».

Смена дня не сбрасывает открытую карточку. Смена статуса закрывает карточку и на телефоне открывает список.

### 5.3. Строка лида

Слева направо на ширине от 640:

1. Метка статуса.
2. Знак источника. Подпись источника есть у скринридера.
3. Имя. Пустое имя показывается «Без имени».
4. Телефон моноширинными цифрами в формате, который уже даёт поле. Пустой телефон: «нет номера».
5. Одна строка заметки, если она есть. Длинная обрезается.
6. Машина: миниатюра и название основной привязанной. Если привязано несколько, после названия «+N». Нажатие на этот блок, а не на строку, открывает досье машины и переключает режим на «Авто».
7. Если привязки нет, а текст авто есть: текст без миниатюры и пометка «не со склада».
8. Время. Для нового лида время создания, для остальных время следующего шага. В просрочке и в поиске время с днём: «Вчера, 14:20», «Сегодня, 14:20», «5 окт, 14:20».

Ниже 640 машина уходит второй строкой под телефоном, миниатюра 32.

Нажатие на строку открывает карточку. Выбранная строка остаётся отмеченной, пока карточка открыта.

## 6. Поиск

Поиск работает в «Дне» и в «Базе» одинаково и заменяет текущий список. В «Авто» то же поле фильтрует машины, см. раздел 7.

Первые совпадения берутся из уже открытой живой ленты сразу. Параллельно один раз за сессию читается вся коллекция лидов. Повторный ввод новый полный запрос не делает. Очистка поиска возвращает режим, который был выбран.

Совпадение, без учёта регистра:

- имя, телефон как текст, текст авто, заметка;
- цифры запроса длиной от 3 входят в цифры телефона;
- имя, марка, модель и год привязанной машины.

Порядок результатов: более новый `createdAt` выше. Заголовок: «Вся база» и число. У строки полная дата.

Пусто после окончания чтения: «Ничего не нашлось». Пока чтение идёт и совпадений ещё нет, видны скелетоны, а не пустая фраза.

Ошибка чтения архива: остаются совпадения живой ленты, над ними «Всю базу прочитать не удалось» и «Повторить». Повтор заново запрашивает архив.

Поиск не создаёт утренние, дневные и вечерние секции.

## 7. Режим «Авто»

Три фильтра под полосой: «С клиентами», «Весь склад», «Проданные». По умолчанию «С клиентами». Фильтр на время сессии, в хранилище не пишется.

Карточка машины: кадр, название с годом, цена в долларах с разделителями, пробег если есть, строка «N клиентов». Приезды и звонки дописываются в ту же строку, когда их больше нуля. Проданная карточка носит подпись «Продана».

Сортировка: больше рабочих лидов выше. При равенстве — по названию.

### 7.1. Что попадает в фильтр

Рабочий лид для счётчика машины — статус из живой ленты, и машина есть в его `carIds` или в основной машине.

- «С клиентами», поиск пуст: в наличии и есть хотя бы один рабочий лид.
- «С клиентами», поиск не пуст: в наличии, даже если рабочих лидов нет, если совпала машина или её лид.
- «Весь склад»: все в наличии, включая машины без лидов.
- «Проданные»: только проданные.

Поиск машины смотрит название, марку, модель, год, цену и любого привязанного лида по тем же правилам, что раздел 6.

Пусто:

- «С клиентами»: «Нет машин с открытыми клиентами».
- «Весь склад»: «На складе нет машин в наличии».
- «Проданные»: «Проданных машин нет».
- При непустом поиске: «Такой машины нет».

### 7.2. Досье

Открывается вместо сетки. Слева закрытие, затем кадр 96, название, цена, пробег, «Продана» если продана, ссылка «На сайте» в новой вкладке на `https://belautocenter.by/catalog/{id}`. Справа кнопка «Клиент»: открывает создание лида уже с этой машиной.

Вкладки: Активные, Приезды, Звонки, История. В подписи вкладки число.

- Активные: рабочие статусы.
- Приезды: только Приезд.
- Звонки: Перезвонить и Недозвон.
- История: Оформился, Отказ, Отказ банка, Брак.

Список по вкладке: более поздний следующий шаг выше, иначе более позднее создание. Под строкой, если шаг задан, подпись статуса и даты шага.

Досье читает все лиды с этой машиной, включая закрытые, и сливает их с живой лентой. Живые строки видны сразу. Пока архив машины читается, под вкладками скелетоны. Ошибка архива не прячет живые строки. Над списком: «Закрытые заявки по этой машине не загрузились» и «Повторить».

Пустая вкладка: «В этой вкладке никого».

Закрытие досье возвращает сетку и тот фильтр, который был. Клавиша Escape закрывает досье, если карточка лида не открыта.

Если склад не загрузился, сетки нет. Экран: «Склад не открылся» и «Повторить». Это не пустой салон.

## 8. Режим «База»

Без поиска: страницы по 50 лидов, сначала новые по `createdAt`, любые статусы. Внизу «Ещё», пока полная страница вернулась. После короткой страницы кнопки нет.

Первый заход показывает скелетоны. Ошибка первой страницы: «Базу открыть не удалось» и «Повторить». Ошибка следующей страницы оставляет уже показанное и пишет «Дальше прочитать не удалось» с «Повторить». Повтор догружает, а не заменяет список.

Поиск в «Базе» заменяет страницы результатом раздела 6.

Закрытые статусы видны здесь и открываются той же карточкой.

## 9. Карточка лида

Лист справа, ширина до 760, на ширине до 767 на весь экран. Фон за листом затемняет раздел. Нажатие по фону закрывает лист по правилу несохранённых правок.

Шапка: «Закрыть», источник, удаление. Источник меняется сразу в черновике. Удаление не в шапке цветом тревоги, пока диалог не открыт.

Имя — крупное поле без рамки. Пустое хранится пустым, в списке читается «Без имени».

Телефон форматируется тем же правилом, что сейчас. Рядом «Копировать». После копирования значок две секунды показывает, что скопировано. «Позвонить» ведёт на `tel:` и видно только когда в номере не меньше 9 цифр.

Если IP уже есть, он показан и есть действие «Заблокировать». Если IP нет, действие «Указать IP». Оба открывают тот же диалог блокировки.

Если тот же номер уже есть у другого лида, под телефоном строка: имя, статус и «Открыть». Сравнение по последним 9 цифрам, порог 7 цифр. Нажатие переходит к тому лиду по правилу раздела 18. Создание и сохранение из-за дубля не блокируются.

Дальше блок машины.

- Есть привязка: кадр 16:9, название, год, цена, пробег, «В наличии» или «Продана». Основная машина помечена «Основная». Остальные компактнее. У каждой «Сделать основной» и «Убрать». Нажатие по кадру или названию открывает досье. «На сайте» открывает каталог.
- Рабочий лид и проданная основная машина: строка «Машина уже продана».
- Текст без склада: поле текста и спокойная пометка «К складу не привязано».
- «Со склада» открывает выбор машины.
- Несколько машин допустимы. Первая выбранная становится основной, если основной ещё не было. Удаление основной назначает основной следующую. Удаление последней очищает основную, текст в поле не стирает.
- Поле текста остаётся всегда: «Марка, бюджет или комментарий к авто». Автопривязка его не затирает, если человек уже что-то написал. При первой привязке, если поле пустое, в него пишется название машины.

Для лида из Meta под машиной одна тихая строка происхождения:

- пара найдена: «Из объявления Meta»;
- пара не найдена: «Объявление Meta без машины на складе»;
- человек явно отвязал объявление от машин: «Объявление Meta без автомобиля».

Статус и следующий шаг стоят одним блоком. Смена статуса в черновике не пишет историю до «Сохранить». Для В работе, Приезд, Перезвонить, Недозвон и Думает дата обязательна. Без неё «Сохранить» не нажимается, под блоком «Нужна дата следующего шага». Для Нового, Оформился, Отказ, Отказ банка и Брака дата не обязательна. Уже выбранная дата при смене статуса не стирается.

Выбор даты сохраняет текущие пресеты и ручную дату.

Заметка — многострочное поле. Плейсхолдер: «Что сказал и что обещали».

Активность: история снизу вверх, сначала последнее. У записи метка статуса, дата и время, кто изменил, комментарий если есть. Пустая история: «Изменений пока нет».

Нижняя панель появляется только когда черновик отличается от сохранённого лида. На ней «Сохранить». Ошибка записи оставляет черновик и пишет «Не сохранилось». Повторная попытка той же кнопкой.

Успешное сохранение прячет панель. Если статус ушёл из живой ленты, лист остаётся открытым, строка из «Дня» уходит сама. История на листе дополняется новой записью после прихода снимка.

Пока лист открыт, внешнее обновление того же лида подхватывается, если черновик не грязный. Если грязный, внешнее обновление не затирает поля. Над панелью: «Эту заявку изменили в другом месте» и «Показать новое». «Показать новое» заменяет черновик серверными данными.

Закрытие с грязным черновиком спрашивает: «Закрыть без сохранения?» Действия: «Остаться» и «Закрыть». Чистое закрытие спрашивает ничего.

Удаление спрашивает: «Удалить клиента?» и «Это нельзя отменить». «Отмена» и «Удалить». Ошибка удаления оставляет диалог и пишет «Удалить не удалось». Успех закрывает лист. Фокус возврата не обязателен, список просто без этой строки.

## 10. Новый клиент

Лист по центру на столе, снизу на телефоне. Заголовок «Новый клиент».

Поля: имя и телефон обязательны, источник, статус, дата следующего шага, машины, текст авто, заметка. По умолчанию источник «Звонок», статус «Новый», дата пустая.

Открытие из досье сразу кладёт эту машину в список и в основную, текст заполняется названием, если поле пустое.

Дубль номера показывается так же, как в карточке, и не запрещает создать ещё одну заявку. «Открыть» закрывает создание и ведёт к существующему лиду. Несохранённый черновик создания при этом спрашивает о закрытии, если имя, телефон, заметка или дата уже заполнены. Одна заранее подставленная машина из досье сама по себе черновик не пачкает.

Правило обязательной даты то же, что в карточке.

«Создать» не нажимается без имени, телефона и нужной даты. Ошибка: лист остаётся, «Создать заявку не удалось». Успех закрывает лист. Новая заявка в живой ленте выделяется на 2,4 секунды и прокручивается в центр. Если её статус не из колонки «Дня», режим становится «База», поиск подставляется телефоном, карточка открывается.

Повторное нажатие во время запроса не создаёт вторую запись.

## 11. Выбор машины

Открывается поверх карточки или создания, на всю их площадь. Поиск «Марка, модель, год». Счётчик найденных. Переключатель «Показать проданные» / «Скрыть проданные». Сначала проданные скрыты.

Строка: кадр 64, название с годом, цена, «Продана» если продана. Уже выбранная помечена «Уже привязана». Повторное нажатие на неё не добавляет копию и закрывает выбор.

Выбор свободной добавляет её и закрывает выбор.

Пустой поиск при живом складе: «Такой машины нет». Пустой склад в наличии и выключенные проданные: «В наличии ничего нет». Ошибка склада: «Склад не открылся» и «Повторить». Закрытие выбора возвращает к черновику без изменения списка.

## 12. Блокировка IP

Поведение сервера сохраняется. В ТЗ не переносятся пароли, ключи и строки подключения.

Диалог спрашивает IP, пароль админки и включает по умолчанию «Отметить заявку как брак». Пустой IP: «Укажите IP». Непохожий на адрес: «Введите корректный IP». Пароль пустой: «Введите пароль». Неверный пароль: «Неверный пароль», заявка не меняется. Адрес петли отклоняется текстом сервера, заявка не меняется.

Успех с отметкой брака: сервер ставит статус Брак и пишет в историю «IP заблокирован: …». Лист показывает этот статус, когда снимок обновится. Повторная блокировка того же IP обновляет причину и не создаёт вторую строку блокировки.

Успех без отметки брака: статус лида не меняется.

Ошибка сети: «Заблокировать не удалось», введённый IP остаётся.

Закрытие диалога не трогает черновик имени и заметки.

## 13. Привязка к складу

Источник истины для рекламы — пары Ads Manager на сайте, кампания `120253765431470202`. Ручная пара важнее автопары. Автопара ставится только когда в наличии ровно одна машина с той же маркой, моделью и годом. Несколько роликов одной машины делят один `carId`. Объявление, которое человек пометил как «не автомобиль», машину не получает.

CRM в момент приёма не подбирает машину по похожести названия. Она записывает только тот `carId`, который прислал сайт, либо который человек выбрал руками.

Поздняя правка пары в Ads Manager уже созданные карточки не переписывает. Их связывает менеджер в карточке. Отдельной кнопки «перепривязать всех» в интерфейсе нет.

### 13.1. Поля, которые сайт передаёт в CRM

К уже существующим имени, телефону, тексту авто, источнику, заметке, статусу и флагу телеграма добавляются, когда они известны:

| Поле | Смысл |
| --- | --- |
| `carId` | Машина склада |
| `adId` | Объявление Meta |
| `leadgenId` | Идентификатор лида Meta |
| `linkKind` | `linked`, `unmatched` или `none` |
| `linkSource` | `user`, `auto`, `site` |

`linked` — пара есть и машина есть в таблице склада. `unmatched` — объявление есть, пары нет или машины уже нет в базе. `none` — объявление явно без автомобиля.

CRM пишет `carIds: [carId]`, `primaryCarId`, и кладёт эти поля в `payload`. Текст `car` остаётся названием объявления или названием с сайта. Существующий ручной `carId` у уже сохранённого лида повторный пакет не затирает: см. идемпотентность.

### 13.2. Один раз для уже лежащих заявок

После выкладки выполняется один проход по лидам источника `instagram`, у которых нет ни одной машины.

Сопоставление только точное, по текущим парам кампании:

- если в пакете лида есть `adId` и у этого объявления есть пара, пишется она;
- иначе текст авто сравнивается с названием объявления без учёта регистра и краевых пробелов;
- одно название ведёт на одну и ту же машину, даже если роликов несколько: пишется она;
- одно название ведёт на разные машины или ни на одну: лид пропускается;
- лид, где машины уже есть, не трогается;
- закрытые статусы тоже можно дописать, если пара точная.

Проход считает: связано, пропущено, неоднозначно. Результат остаётся в отчёте сдачи, не в интерфейсе. Повторный проход безопасен: уже заполненные не меняются.

## 14. Вход лида из Meta

Цепочка прежняя. Meta вызывает сайт. Сайт читает лид в Graph, один раз пишет его у себя, шлёт в CRM и одно сообщение в Телеграм. Опрос по расписанию не добавляется.

Сайт перед отправкой в CRM читает пары Ads Manager.

Сценарии:

1. Объявление связано с машиной в наличии. В CRM уходит `linkKind=linked`, `linkSource` равен `user` или `auto`, `carId`, `adId`, `leadgenId`. Карточка открывается с кадром, ценой и подписью «Из объявления Meta». Телеграм по-прежнему содержит имя, телефон и название авто.
2. Объявление связано с уже проданной машиной. Привязка всё равно пишется. В карточке «Продана» и, пока лид рабочий, «Машина уже продана».
3. Объявление ждёт выбора, название слишком короткое, год не сошёлся или подходящих машин несколько. `linkKind=unmatched`, `carId` пустой, текст авто — название объявления. Карточка без кадра, с пометкой «не со склада».
4. Человек пометил объявление как не автомобиль. `linkKind=none`. Машина не ставится.
5. Пара указывает на машину, которой уже нет в складе. Сайт шлёт лид как `unmatched`. Заявка не теряется.
6. Настройки пар прочитать не удалось. Лид всё равно уходит в CRM с названием объявления и `unmatched`. Заявка не отклоняется из-за рекламного шкафа.
7. Graph не отдал лид. Сайт отвечает ошибкой, в CRM пустая карточка не создаётся, у себя лид не помечается доставленным. Meta сможет повторить.
8. CRM не приняла лид. Сайт отвечает ошибкой и не помечает доставку. Телеграм в этом проходе не отправляется, чтобы не сообщить о заявке, которой в CRM нет.
9. Повтор того же `leadgenId`. Сайт, если уже пометил доставку, ничего не шлёт. Если пометка потерялась и пакет пришёл снова, CRM находит существующую карточку по `payload.leadgenId`, отвечает успехом и тем же id, вторую карточку не создаёт, Телеграм CRM не шлёт.
10. В одном вызове Meta несколько лидов. Каждый обрабатывается отдельно. Ошибка одного не помечает остальные доставленными. Ответ сайта ошибочный, если хотя бы один не доставлен.
11. Подпись вебхука не сошлась. Сайт отвечает отказом, CRM не вызывается.
12. Имя или телефон в форме пустые. Карточка создаётся. Имя с сайта, если его нет, остаётся «Не указано», как в текущей отправке. Телефон может быть пустым.

Журнал приёма не печатает тело заявки, телефон и имя.

## 15. Вход лида с сайта

Формы сайта по-прежнему пишут заявку в базу сайта и, когда отправка в CRM включена, зовут тот же вебхук. Тип «новый автомобиль в каталоге» CRM не получает.

Если у формы есть `carId` карточки каталога, он уходит в CRM. `linkSource=site`, `linkKind=linked`, когда эта машина есть. Текст авто собирается как сейчас из марки и модели. IP, если он известен, по-прежнему уходит в карточку.

Заявка со страницы машины, заявка на просмотр и кредитная заявка с известной машиной открываются в CRM уже с кадром.

Заявка без машины — сообщение с сайта, продажа автомобиля клиента, гарантия — остаётся текстом. Машина по марке и модели не подбирается.

Ошибка доставки в CRM не ломает сохранение заявки на сайте и не отменяет Телеграм сайта. Это текущее поведение, оно сохраняется: сайт уже сохранил человека у себя.

Повтор той же отправки формы может создать вторую карточку. Отдельного ключа идемпотентности у формы сайта нет, и в этой сдаче он не вводится. Дубль виден менеджеру по номеру.

## 16. Ручной лид и правка машины

Менеджер может привязать, сменить и снять машину независимо от того, что прислала реклама. Снятие последней машины оставляет текст. Происхождение «Из объявления Meta» в пакете не стирается: оно объясняет, откуда пришла заявка, даже если машину потом поправили.

Ручная привязка пишет историю только через обычное сохранение карточки. Отдельной строки «машину сменили» нет: в истории остаётся смена статуса, как сейчас. Смена одной только машины без смены статуса историю статуса не плодит.

## 17. Статусы и дата. Сценарии менеджера

1. Новый лид из рекламы лежит в «Новых», в группе своего дня, без даты шага.
2. Менеджер ставит «В работе» без даты. Сохранить нельзя, пока дата не выбрана.
3. Ставит «Перезвонить» на завтра. После сохранения лид уходит из «Новых» в «Перезвон». На завтра он в группе этого дня. На сегодня его нет.
4. Дата шага вчера, сегодня открыт «Перезвон». Лид в «Просрочено», в подгруппе «Вчера».
5. «Приезд» на сегодня. Лид в «Приезде», группа «Сегодня».
6. «Недозвон» и «Думает» ведут себя как рабочие статусы с обязательной датой и своим столбцом.
7. «Оформился/купил». Дата не нужна. Лид покидает «День». В «Базе» он есть. В досье машины он на вкладке «История». Конверсия уходит один раз.
8. «Отказ» и «Отказ банка» так же уходят в базу и в историю досье. Конверсия не уходит.
9. «Брак/Тест» вручную или через блокировку IP. В «Дне» строки нет. В базе есть.
10. Возврат из «Отказа» в «В работе» требует дату, возвращает лида в живую ленту и в нужный день.
11. Два менеджера. Один держит грязный черновик, второй сохранил статус. Первый видит «Эту заявку изменили в другом месте» и сам решает, показывать ли новое.

## 18. Дубль номера

Проверка идёт по всей базе, как только архив прочитан. До этого проверка идёт по живой ленте и уже открытым страницам базы. Если полное чтение упало, строка дубля не выдумывается. Под телефоном: «Номер по всей базе проверить не удалось».

«Открыть» у дубля:

- рабочий статус: режим «День», нужная колонка, дата шага или сегодня, если шаг в прошлом для сегодняшнего экрана просрочки, карточка этого лида, строка в центре;
- закрытый статус: режим «База», поиск по телефону, карточка открыта.

Если у номера больше одной чужой заявки, показывается самая новая. Остальные находятся поиском.

## 19. Отказы экрана

| Что сломалось | Что видит менеджер | Что происходит с данными |
| --- | --- | --- |
| Живая лента не открылась | «Заявки не обновляются» и «Повторить». Последний удачный список остаётся, если он был | Запись не затирается пустым экраном |
| Склад не открылся | «Склад не открылся» и «Повторить». Текстовые авто в строках остаются | Привязка в карточке не стирается локально |
| База, первая страница | «Базу открыть не удалось» | Ничего не удаляется |
| База, следующая страница | Уже показанные строки и «Дальше прочитать не удалось» | Показанное остаётся |
| Архив поиска | Совпадения из живой ленты и ошибка с повтором | — |
| Архив досье | Живые лиды машины и ошибка с повтором | — |
| Сохранение карточки | «Не сохранилось», черновик на месте | Повтор той же кнопкой |
| Создание | «Создать заявку не удалось» | Повтор не плодит лишнюю запись, пока первый запрос не кончился |

| Фото не грузится | Запасная поверхность с буквой марки | Строка не меняет высоту |

| Нет входа | Текущий вход CRM | Раздел не мигает чужими данными |

Каталог машин читает только переменную окружения базы. Запасная строка подключения в коде маршрута убирается. Если переменной нет, маршрут отвечает отказом, а экран показывает «Склад не открылся». Значение строки в документы и журналы не попадает.

## 20. Клавиатура

Вне полей ввода:

- `/` фокусирует поиск.
- Escape закрывает верхний слой: выбор машины, затем диалог удаления или закрытия без сохранения, затем блокировку IP, затем карточку, затем досье.

В поле ввода Escape поле не очищает и карточку не закрывает. Так черновик не пропадает от случайной клавиши.

Фокус виден на режимах, статусах, строке, кнопках, полях и вкладках.

## 21. Вне этой сдачи

Не делаем в этом проходе:

- новые статусы, в том числе «В лизинге» и «Передан в лизинг», и воронку с ответственным менеджером;
- отдельные очереди «без машины» и «ждут слишком долго» как новые режимы;
- переписывание бокового меню CRM и остальных разделов;
- правку кампаний Meta из CRM;
- подбор машины по нечёткому названию;
- автоматическое обновление старых карточек при каждой будущей правке пары в Ads Manager;
- идемпотентность обычных форм сайта;
- опрос лидов по расписанию.

В карточке нового лида время с создания видно по дате в активности и по времени в строке. Отдельный таймер «ждёт 2 часа» не добавляется.

## 22. Приёмка

Сдача принимается, когда на ширине 375 и 1440 пройдены сценарии ниже. Внешний вид сверен с разделом 3: нет белых капсул выбора, нет прописных подписей полей, нет экрана из одной фразы «Загрузка…», у строк и карточек есть воздух, статус читается меткой, машина с парой показывает фото.

Функциональные проверки:

1. Новый рекламный лид с готовой парой появляется в «Новых» с фото и ценой без ручной привязки.
2. Рекламный лид без пары появляется с текстом объявления и пометкой «не со склада».
3. Повтор того же лида Meta не создаёт вторую карточку.
4. Заявка со страницы машины на сайте приходит с этой машиной.
5. Заявка «написать нам» без машины приходит текстом.
6. «Сегодня» в рабочем статусе — один список плюс отдельно «Просрочено», без утро / день / вечер.
7. Поиск по куску телефона находит старую закрытую заявку.
8. Дубль номера предлагает открыть существующую заявку и не запрещает сохранить новую.
9. Рабочий статус без даты не сохраняется.
10. «Оформился» уходит из «Дня» в базу и в историю машины.
11. Досье проданной машины открывает историю.
12. Грязное закрытие спрашивает подтверждение.
13. Ошибка склада не выглядит как салон без машин.
14. Блокировка IP с отметкой брака переводит карточку в Брак.
15. Комиссия и SMM в раздел не входят.

Код пишется после принятия этого ТЗ. Первым меняется внешний вид CRM, затем приём пары на сайте и в вебхуке CRM, затем одноразовый проход по старым рекламным лидам.
